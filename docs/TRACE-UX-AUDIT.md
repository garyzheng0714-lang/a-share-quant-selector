# QSelect 前端 TRACE / Astryx 验收记录

## 1. 结果契约（Truth）

当个人 A 股研究者打开每日股票池时，帮助他通过添加、拖动、排序和查看策略，得到可解释的单策略命中与多策略 AND 交集，并能进入 K 线后返回且恢复研究上下文；页面保持亮色、数据真实、操作可撤回，所有可见 UI 由项目锁定版本的 Astryx 组件、主题和令牌承载。

- 当前痛点：旧页面混用原生控件、图标库和动效库，暗色/亮色不一致，策略组合与结果之间的关系不够直观。
- 本轮结果：`/stocks` 成为策略工作台权威入口；真实 API 数据驱动策略库、扫描结果和 K 线，不再依赖演示数据。
- 明确非目标：不改股票因子算法、后端数据口径和权限模型；ECharts 仅作为 K 线这一领域数据可视化实现，不承担通用 UI 组件职责。

## 2. 方案选择（内部 Judge）

| 方案 | 任务路径 | 取舍 |
| --- | --- | --- |
| A：筛选器 + 结果表 | 先选条件，再看结果 | 认知简单，但策略顺序和组合关系不可见 |
| B：右侧抽屉式策略库 | 结果优先，策略按需打开 | 移动端友好，但桌面端拖动组合不连续 |
| C：三列数据工作台（采用） | 策略库 → 组合画布 → 命中结果 | 保留拖动、AND 关系、单策略检查和结果核验；移动端改为顺序堆叠并用 Dialog 收纳策略库 |

采用 C，因为它直接呈现“总池子 → 条件组合 → 交集结果”的数据关系，同时把复杂策略库渐进披露到移动端。

## 8. 数据管线与首屏减负 TRACE 验收（2026-08-08）

### 产品与结果契约

- 产品目的：让个人 A 股研究者能在数秒内确认“数据是否可用、今天有什么结论、有什么要处理”，并能进入详情追溯来源、时间、任务和存储。
- 目标用户：每日复盘、但不想先理解运维细节的个人研究者。
- 核心任务：首屏完成三项快速判断；有疑问时打开数据管线页，证明同一份快照被采集、发布、决策和 K 线回读。
- 期望情绪：先是放松和清楚，再是可控和可追溯；不用一屏读完全部系统细节。
- 关键约束：只显示真实 API 状态；页面 GET 不触发抓取；研究候选不得写成交易动作；手机和桌面均无水平溢出；已确认的长期保留策略必须由后端状态真实表达且不触发异常提示。

### 方案选择

| 方案 | 取舍 |
| --- | --- |
| 继续在首屏展示完整系统状态 | 信息全，但它在用户看板块和结论前先制造运维负担 |
| 完全隐藏数据状态 | 首屏干净，但无法快速判断数据是否可信 |
| 三项摘要 + 独立详情页（采用） | 首屏只保留数据、结论和异常；来源、任务路径、存储和保留渐进披露 |

## 9. 云阶情报与环境仪表盘 TRACE 验收（2026-08-09）

- 产品目的：围绕云阶唯一入围规则，把市场温度、板块强弱、近期消息和可追溯优先级压缩到一个首屏决策路径。
- 目标用户：每天收盘后快速判断云阶候选和仓位强度的单一研究用户。
- 核心任务：确认今日是否命中、第一/第二推荐、所属行业排名与热度、是否值得买入，再按需展开 K 线和消息证据。
- 期望情绪：明确、低压力、可信、可控。
- 关键约束：云阶决定入选；市场温度只调整执行强度；固定证据公式排序；AI 只引用已落账事件；情报截止不得晚于信号交易日；正式快照与决策证据长期保留。
